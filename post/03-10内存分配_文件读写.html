滴水逆向 03-10 内存分配_文件读写

2026-10-22 | 滴水逆向三期

程序的执行步骤：源代码 → 替换 → 编译 → 链接 → 装入内存 → 执行

具体地，替换通常指预处理阶段，预处理器会把宏、头文件、条件编译等内容展开或替换成实际代码；编译就是将诸如 C 代码翻译成硬编码（汇编）；链接阶段是因为代码中可能还引用了别人的函数或者代码，就要将所有编译的目标模块链接起来装入模块，形成完整的逻辑地址；最后装入内存，等待CPU的分配执行。

本节讲的就是替换阶段做的事情，也就是编译器前

宏定义

1、无参数的宏定义

  • 一般形式：#define 标识符 字符序列

    与 typedef 不同，typedef 是在编译时替换的，#define 是在编译前的预处理时就替换了的。以及 #define 可以定义任何东西，typedef 只能定义类型名；
    与 const 也不同，const 是在常量区开辟了内存，然后将内存地址引用过来，但是 #define 是直接替换，不会单独分空间。
    所以类似于 PI 或者文件路径等一些确定不会改变的东西，就可以用 #define 整个东西来代替。

  • 注意事项：

    • 只作为字符序列的替换工作，不作任何语法检查
    • 如果宏定义不当，错误要到预处理之后的编译阶段才能发现

2、带参数的宏定义

  • 一般形式：#define 标识符(参数表) 字符序列

    相比使用函数，虽然效果一样，但是函数需要额外开辟一块内存，分配额外的堆栈空间，而宏定义只是进行简单的替换

  • 注意事项：

    • 宏名标识符与左圆括号之间不允许有空白符，应紧接在一起

    • 宏与函数的区别：函数分配额外的堆栈空间，而宏只是替换

    • 为了避免出错，宏定义中给形参加上括号

    • 末尾不需要分号

    • define可以替代多行的代码，记得后面加 \

内存分配与释放

我们前面学过静态申请内存，比如int x、char arr[20000]，这些都是我们知道要申请多大的情况下的，但是如果我不知道要存的东西有多少，就要动态申请内存

malloc 函数做的事情就是在堆上挖一块内存空间，并返回一个指向它的指针，如果内存空间不够，则返回 NULL。

其中，size_t 是一个 typedef 的 unsigned int（4字节），专门用来表示大小，sizeof 运算符的返回值类型就是 size_t。
void* 表示任何类型的指针，因为使用 malloc 动态申请内存，最后要返回一个指向整块内存的指针，但是不知道具体是一个什么类型的指针，那么返回值类型使用 void*。并且因为宽度是不确定的，所以 void* 类型指针无法做++/-- 等运算。void* 相当于一个临时的类型，和其他指针类型是一样的占 4 字节，在使用时需要强转 int *p = (int*)malloc(...)。

malloc 用完了一定要记得释放。不同于全局变量与局部变量，全局变量分配在全局变量区，程序加载到内存时就分配好了，运行期间一直在，程序结束时被回收；局部变量分配在栈上，使用完后变成垃圾数据不用管，下一次再使用时会直接覆盖。但是 malloc 不一样，malloc 分配的内存在堆中，堆中的内存分配时，操作系统会记住哪块已经分出去了，如果不结束程序，这块内存就被锁住了别的用不了。所以如果用 malloc 申请了一堆又不释放，内存占用率就会越来越高，程序就会崩溃，所以用完了一定要记得释放内存。

.exe 程序运行时会分配 4GB 的虚拟内存，进程与进程之间相互独立，如果越界访问了不属于自己的地址就会报错。

注意事项：

  • 使用 sizeof(类型)*n 来定义申请内存的大小
  • malloc 返回类型为 void* 类型，需要强制转换
  • 无论申请的内存有多小，一定要判断是否申请成功
  • 申请完空间后要记得初始化
  • 使用完一定要是否申请的空间
  • 将指针的值设置为 NULL

课后作业

  1. 用十六进制文本编辑器，打开一个记事本的 .exe 文件，再打开在内存中的记事本进程，记录下这两个文件的不同
    可能是 winhex 用的盗版还是啥原因，内存里面根本找不到记事本，就不实操了，看别的师傅以及 ds 的总结，不同点主要为以下：
    磁盘上的 .exe 是存储格式，按 FileAlignment（如 0x200）紧凑布局；内存中的进程镜像是执行格式，按 SectionAlignment（如 0x1000）布局。因此，同一份代码和数据，在内存中会被“拉伸”到更大的地址范围，节与节之间的空白填充会变长，各节的起始偏移也会变为内存页大小的整数倍。但节内的实际内容不变，头部和节表的结构也保持对应。起始地址的差异（0 vs 基址）则源于“文件偏移”和“虚拟地址”两种不同地址空间的定义。
